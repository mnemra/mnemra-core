# P-0031: Test-substrate isolation

## Status

`accepted` — authored `proposed` 2026-10-19 at the #4018 gate (ruling 7793, ADR 6). Accepted 2026-10-19 by the maintainer (#4018 activity 7800) with the operator-run Postgres amendment at commit `08f4b8e`. The CI tier-2 spec (`docs/specs/2026-07-02-ci-flake-tier2-shared-engine.md`) still names the embedded engine; its amendment is #4119 and this ADR states what transfers.

## Context and Problem Statement

With no embedded engine, every Postgres-backed test needs a server it did not start. The repository has already been burned by a skip-with-no-assertion trap and by a cross-lane reap of another session's postmaster (`CLAUDE.md`), so the substrate must fail loudly when absent and must never touch another run's objects. Two lanes share one machine and may share one server; CI runs a service container; the host-under-test must satisfy R-0117-c, which the harness role (which needs `CREATEDB` and `CREATEROLE`) cannot; a superuser connection is needed for a handful of negative tests and nowhere else; PostgreSQL truncates identifiers at 63 bytes silently; and the production-store guard must not fail open on a database the harness cannot connect to.

## Decision Drivers

- **No skip, no environment-dependent red** (`P-TrustworthySignal`; R-0018-b — a real Postgres, never a mock).
- **The server is an injected input** (`P-TestableByDesign`).
- **Least authority** — superuser confined to one binary; the host-under-test never runs as the harness role (`P-LeastAuthority`).
- **Fail closed on the production-store guard** (`P-SecurityLayered`).
- **One mechanism for local, CI and smoke** (V-Consistency); the supply chain of the CI image pinned by digest with a firing bump (`P-SecurityLayered`; Dependabot is disabled here).

## Considered Options

1. **Operator/CI-provided server, two required URLs, three roles per run, template databases, gate-level run id, dead-pid and age sweeps, confined superuser, fail-closed guard, digest-pinned service with a bump trigger (chosen).**
2. **A fixture-started disposable cluster from the operator's `initdb`/`pg_ctl`.**
3. **Skip Postgres tests when no server is configured.**
4. **One role for harness and host-under-test.**

## Decision Outcome

Chosen option: **1.** The fixture reads `MNEMRA_TEST_DATABASE_URL` (harness role: `LOGIN CREATEDB CREATEROLE`, not superuser) and `MNEMRA_TEST_SUPERUSER_URL` (read by one gated binary only, enforced by a source check); either absent or unreachable fails the first acquiring test by name. Per run it creates a run-scoped owner and serving role so the smoke host satisfies R-0117-c, and per test a database cloned from `mnemra_test_template` (pgvector pre-installed by the setup). `<run>` is the gate invocation — `MNEMRA_TEST_RUN_ID` exported once by `just ci`, generated by a standalone binary otherwise — as `<hosthash>_<pid>_<epoch>`, the hash over hostname, boot id and container id, every name built to fit 63 bytes and parsed from the right. Before provisioning, the fixture refuses a server holding any non-test database that carries the migrations table or that it cannot connect to, caching the scan per run. The sweep removes the run's own objects, same-hash objects whose pid is dead or whose epoch mismatches, and any `mnemra_test_*` object older than 24 h; it never touches another hash's live run (pid-namespace limit stated). CI provides a digest-pinned pgvector/PostgreSQL 16 service with a `pg_isready` wait, a scheduled workflow that fails when the tag's digest moves, an env-unset step proving fail-not-skip, a `just ci` preflight naming the variables, and a fresh-machine job inside the required "CI gates" check that runs the documented operator path end to end. Expected failures for the two implementation-time transport mechanisms are named entries with a signature, a count pin, an admission rule and an sqlx-version exit detector. *(Anchors: R-0018-b; `P-TrustworthySignal`; `P-TestableByDesign`; `P-LeastAuthority`; `P-SecurityLayered`; `P-CheckCoversTheClaim` — "a fresh machine reaches serving" is claimed only by a job that does it; V-Consistency; maintainer ruling 7091 — no host-driven lifecycle.)*

**Implemented by** spec R-0120-a through R-0120-h and R-0121-c in `docs/specs/2026-05-24-mnemra-core-v0-substrate.md`; the tier-2 spec's own amendment (#4119) restates its R-0026/R-0027/R-0032 words against this.

### Consequences

**Good:** no test can run against a production store, start a server, skip silently, or sweep another lane's live run; the operator's documented setup path is the tested path; the host-under-test is exercised as exactly the role it will run as.

**Bad / Trade-offs:** a local developer must provide a server (two documented paths); three roles and a run id are more fixture than before; the 24-hour age sweep assumes no run lives that long (stated); the orchestrator-marker and container-id reads are INFERRED until measured in the CI container.

## Pros and Cons of the Options

### Option 1 (chosen)

- Pro: every trap the repository has recorded has a mechanism and a seeded case.
- Con: the most fixture code of the options.

### Option 2 — fixture-started disposable cluster

- Pro: zero operator setup for tests.
- Con: re-creates the host-driven lifecycle the engine decision rejected (ruling 7091, option 2), and packaging the binaries it would need is #4019's open question.

### Option 3 — skip when unconfigured

- Pro: convenient locally.
- Con: the skip-with-no-assertion class this repository was burned by; coverage narrows while the gate stays green.

### Option 4 — one role for harness and host

- Pro: simpler.
- Con: cannot satisfy R-0117-c (the harness needs `CREATEDB`); the smoke host could never serve.
